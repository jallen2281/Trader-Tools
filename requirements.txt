# Version policy, learned the hard way.
#
# An unbounded ">=" took production down once already: a rebuild that touched none of this
# code resolved SQLAlchemy 2.1, which changed the default postgresql:// driver, and every
# pod failed readiness. So framework-level dependencies carry an upper bound at the next
# major -- a major version arrives because something broke on purpose, and it should
# arrive when someone is watching, not on an unrelated deploy.
#
# Two deliberate exceptions, both left open on purpose:
#   cryptography -- a security library is the one place you want the newest patch the
#                   moment it exists; an upper bound here would block the fix it exists for.
#   yfinance     -- an unofficial scraper that breaks when Yahoo changes its pages, so the
#                   newest release is routinely the only working one.
#
# Four pins below were moved off known-vulnerable versions (OSV, Oct 2026): pillow had 32
# advisories including arbitrary code execution, requests leaked .netrc credentials on a
# malicious redirect, python-dotenv could overwrite files through a symlink, and flask
# omitted a Vary: Cookie header. The Security Scan workflow had been failing on these for
# weeks; it was right.

flask>=3.1.3,<4             # <3.1.3: missing Vary: Cookie on session access
yfinance>=1.2.0               # intentionally unbounded: see the note above
pandas>=2.1.4,<3
numpy>=1.26.2,<3
plotly>=5.18.0,<7
pillow>=12.3.0,<13          # <12.3: 32 advisories incl. arbitrary code execution
ollama>=0.1.6,<1
anthropic>=0.40.0,<1
google-genai>=1.0.0,<2
python-dotenv>=1.2.2,<2     # <1.2.2: symlink following in set_key
ta>=0.11.0,<1
mplfinance==0.12.10b0
matplotlib>=3.8.2,<4
requests>=2.33.0,<3         # <2.33: .netrc credential leak, verify=False bypass
# Held below 2.1 deliberately. 2.1 changes the default postgresql:// driver to psycopg v3,
# which is not in this image, and an unpinned upper bound meant a routine rebuild picked it
# up and took the pods down on readiness. db_config names +psycopg2 explicitly as well, so
# lifting this pin is a decision rather than an accident -- but it still needs psycopg3
# added (or the driver kept) before it can move.
SQLAlchemy>=2.0.0,<2.1
Flask-SQLAlchemy>=3.0.0,<4
psycopg2-binary>=2.9.0,<3
Flask-Login>=0.6.3,<0.7
authlib>=1.2.0,<2
python-jose>=3.3.0,<4
cryptography>=45.0.0          # intentionally unbounded: see the note above
scikit-learn>=1.0.0,<2
